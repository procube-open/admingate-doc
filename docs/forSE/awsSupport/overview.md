# 概要

AdminGate ワークフローの作業申請において IAMポリシーを指定した申請を行なうことで、AWS コンソールへのアクセスを制御することができます。ここでは、その機能と設定手順について説明します。

## 機能内容

- 作業申請が承認されていなければ AWS コンソールにアクセスできない
- 作業申請で承認されたユーザのみが作業できる
- 作業では作業申請で申請されたポリシーで許可されたことのみ実施できる

なお、操作履歴は以下の方法で確認できます。
- 全ての操作は AWS Cloud Trail で記録・監視され、いつでも監査可能である
- セッションマネージャでの SSH 接続はテキストの記録が S3 に残る


## 設定手順

AdminGate では、Keycloak で認証を行い、結果の SAML アサーションを AWS に送り、フェデレーティッドアイデンティティとしてログインします。
そのため、Keycloak を Identity Provider (IdP) 、AWS IAM を Service Provider (SP) として SAML 連携するよう設定します。

また、ワークフローの申請作業に必要な各種ロールや IAM ポリシーの設定を行う必要があります。

手順は以下のとおりです。また、次章以降で各設定手順を例を用いて説明します。

1. IDManager の再構築
    1. AWS アカウントID を設定する
    1. AWS IAM ユーザのアクセスキーIDおよびシークレットアクセスキーを設定する
    1. 環境変数を設定する
    1. イメージの作成およびデプロイを行なう
1. SAML 連携の設定
    1. パート１: Keycloak での設定(1)
    1. パート２: AWS IAM コンソールでの設定
    1. パート３: Keycloak での設定(2)
1. IAM ポリシーの作成
1. IDManager での設定
    1. IDManager の IAM ポリシー管理で、3. で作成した IAM ポリシーを登録する
    1. IDManager でワークフローの申請・承認を行なう

:::note
作業申請に指定する IAM ポリシー名は、IDManager の IAM ポリシー管理で管理されています。また申請に使用するポリシー名は、IDManager の ***ID管理 > IAMポリシー管理*** と AWS IAM コンソールの ***アクセス管理 > ポリシー*** で一致させる必要があります。

ただし、IDManager と AWS IAM のポリシー設定は、それぞれ他方の設定を変更しても自動的に反映されるわけではありませんので、常に一致するようにメンテナンスする必要があります。
:::
